# TASK-EQUIP-027 · 四类装备使用等级提升机制包

## 目标

玩家使用幻魔晶石或幻魔之心提升两职业武器/衣服/头盔/鞋的使用等级，看到源名称/属性/售价变化，按人物等级决定是否能装备，并保存恢复。

## 输入

- 依赖TASK-SHOP-026及025交易、既有共享打造槽和装备属性、人物成长/保存。选择理由：杂货商已能出售幻魔晶石，初始幻魔礼包已有幻魔之心，但材料仍无可用打造入口；补齐采购→装备成长的完整能力。
- frame9/DoAction.as:3150–3190 为flashInfo提示，3704–3754 为makeItem实际升级；3350附近yesButton/useGem负责扣材料、成功后upData。提示提到失败不能据此添加随机失败，必须核对执行函数。
- 已有 docs/reverse-engineering/equipment-magic/source-functions.json 冻结完整makeItem/useGem/yes/upDataWeapon与AS/P-code哈希，可独立消费，禁止覆盖既有原始提取或历史冻结。
- RoleMC.as:119初始xxx_maxLevels=150，686–708为动态上限setter/getter；持久role_maxLevels在frame9/DoAction_2恢复。注册属性/名称表和Inventory装备职业/等级门槛已实现。

## 范围

两材料×两职业×四类装备的共享升级；1→15、低于120时+15、120以上逐级及当前人物上限；晶石按源需求数量、之心单颗；缺材/零数量单件/封顶/非法目标、取消、过期按钮和槽所有权。升级后名称/所有属性和salePrice重新计算，同时保留品质/魔魂/孔/宝石/元素字段。新UI为design。

同步明确当前人物最高等级的持久归属，旧raw.role_maxLevels可推广，人物经验和装备提升共用上限而不硬编码互相矛盾。原始未实现字段仍无损保留。未包含装备元素/镶嵌/幸运符/戒指等级、神品品质来源或区域扩展。

## 输出

docs/reverse-engineering/equipment-level/ 源合同、冻结源引用/验证与覆盖；纯规则模块、共享打造面板升级模式、保存字段推广、逻辑和浏览器检查。

## 验收

- 独立冻结makeItem/useGem/yes oracle 对两职业四类型、1/15/105/119/120/149/150、两材料、0/1/不足/恰好/多余数量、不同人物上限对照结果、扣除、消息和全部重算字段。不得从提示文案制造成功率。
- 正常两职业无probe领取真实装备→城内采购幻魔晶石→提升1到15→因角色低级拒绝装备→正常经验球升级后装备，幻魔礼包/之心路径也可操作；查看属性、关闭重开、旧按钮与切图/新建。
- 保存/刷新/真实导入保留升级装备、打造槽材料、人物上限和raw；满包取回落地可回收，旧回调不重复消耗。
- npm run typecheck、npm test、npm run build、npm run test:browser、npm run check:save；generate:harness/check:harness和实际截图复核。
