# TASK-EQUIP-031 · 装备元素附加与元素石成长

## 目标

玩家给两职业四类装备附加元素，用小/大元素石提高元素数值，穿戴查看单件和同元素套装效果，并保存继续。

## 输入

依赖TASK-NPC-030以及已完成的四装备打造/等级/品质/镶嵌和完整存档。选择理由：物品机制台账已有五元素与两元素石注册，现有装备元素数值重算可消费，人物汇总与打造缺口仍未关闭；原版debug新建已有雷元素，提供真实UI渠道。

精确源：`frame_9/DoAction.as:3779–3910`的makeItem小/大元素石与五元素分支；`equipment.flashAttribute:2050–2078,2182,2230–2255`单件元素/四件同元素套装与属性效果；`upDataWeapon:5360–5489`元素最低值/保留较高值。既有equipment-magic冻结makeItem/useGem/yes可读，不覆盖旧证据；独立冻结完整属性函数及AS/P-code核对。`DefineSprite_4536/frame_2/DoAction.as`debug赠送雷元素，其余材料注册和获取范围须明确。

## 范围

风/火/水/地/雷五元素初次附加、声望10/25、已有元素拒绝；小/大元素石的品质门槛、全部四元素严格小于装备等级门槛、小石随机四分支与大石全加。四装备、两职业、品级与已高于基础数值组合；聚合元素战斗力、元素数值、同元素套装暴击/闪避/攻击/防御。沿用可追踪随机端口，真实检查随机调用次数和消费顺序。

共享打造槽、人物面板、存档数值无损；正常UI使用原版debug雷元素完成同系附加/套装旅程，其他目录受控矩阵，不虚构常规获取。神品品质、神力宝石、魔之魂、战魂、矿洞获取、战斗结算不属于本次。

## 输出

源合同/冻结/字段归属与oracle、元素领域规则及UI、人物属性消费者、保存与覆盖台账、逻辑和浏览器验证。

## 验收

- 全七材料、两职业四装备、声望/数量、品级/等级/四元素临界与全部随机分支对照源完整对象、消费和属性；混合/同系套装、品质/魔魂/孔效果组合验证。
- 两职业无probe原版debug材料附加→四件同元素套装→属性→保存刷新/真实导入；普通新建通用wudi赠送4雷元素（本次源核对纠正原缺材假设），未放入材料如实反馈，其他材料明确受控。
- 已有元素、不足声望/材料、满包回收、旧回调、关闭/切图/新建、源raw和未实现字段保留。
- `npm run typecheck`、`npm test`、`npm run build`、`npm run test:browser`、`npm run check:save`与实际截图复核；generate:harness/check:harness。
