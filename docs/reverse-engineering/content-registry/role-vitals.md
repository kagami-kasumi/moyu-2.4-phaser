# 角色生命、魔力与源泉

正式公式与顺序在 `src/content/role-vital-rules.ts`。RoleMC `flashAttribute`（1120起）先init重置百分比基础，再合并装备百分比；生命基础为职业成长率乘(等级+5)，加技能生命和装备生命，再乘百分比并Math.round。魔力同理。无装备对象时省略装备项。职业成长率在地图初始化设置，不能把构造器的未配置状态当作最终初值。

构造器将lifeSourseLevels/mpSourseLevels设为1；源泉当前值没有构造赋值，缺失编码getter读取0。地图初始化先刷新装备属性，再令role.isAlive=true；该setter将生命和魔力填满到当时上限。容量取对应生命/魔力上限乘源泉等级，写上限或源泉等级都会重新计算。

生命/魔力写入忽略NaN，先储存输入，再先判断大于上限、否则判断小于0。上限本身未限制非负，因此不能将此过程无条件概括为数学上的[0,max]钳制。降低上限只重算源泉容量，不立即钳制已有生命/魔力。源泉当前值的setter不设上下限，允许大于容量或负值；这里记录源语义，不是现代坏档校验政策。

## 读档覆盖顺序

`frame_9/DoAction_2.as:1732–1743` 先写源泉等级、容量和当前值，然后才写生命上限/生命、货币、魔力上限/魔力。后写上限会再次计算容量，覆盖前面读取的源泉容量；源泉当前值不随之钳制。举例：读取源泉等级2、容量999、当前值500，再读生命上限100，得到容量200、当前值500。该差异通过原setter执行验证，不应以“恢复时直接照抄全部字段”替代。

持久字段字典将这些初值登记为有顺序的配方，而非给随机装备、不同职业或后续源入口捏造统一数值。最终初始化流水线仍需与技能、装备及幻兽完整接入核验。本合同不声称完成整个角色初始化。
