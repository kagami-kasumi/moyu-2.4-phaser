# 执行协议

项目硬约束以 [AGENTS.md](../../AGENTS.md) 为准。以下只定义正式任务的操作约定；普通讨论、解释、小修不强制进入任务流程。

## 调度

运行 `npm run task:next`。唯一状态源是 [state.json](../tasks/state.json)：当前治理项优先，之后是当前游戏任务。当前指 Ready / Active / Blocked；Blocked 仍占据当前位置，返回阻塞原因，不跳到别的任务。

读取返回的独立合同及所属覆盖台账，核对输入可用性和前置任务。用户指定其他范围时先调整合同与状态，保持单线单当前项。不得在源证据缺失时直接切到实现。

## 开始与执行

1. 确认合同的验收能回答用户目标，读取必要输入；先窄查再扩读。
2. 将 Ready 更新为 Active，生成派生视图。一次任务默认交付一个可观察、可独立验收的完整能力；取证、转换、实现、测试是任务内里程碑，按证据门禁连续推进。仅在包含互不相关、可分别交付的能力或真实外部依赖时拆分，不因技术阶段、文件数量或上下文长度拆任务。
3. 可并行派发资料调查、独立验收或互不重叠的写入包。简报写明问题、路径、输入、输出、写入边界和停止条件。子 agent 不改调度，主 agent 统一归并。
4. 完成合同要求的实际工作与对应检查。对跨帧、镜像、暂停、命中等行为，检查应能暴露错误，不能只是重复实现公式。
5. 收到新用户消息时纳入当前工作；用户明确停止/改范围则同步记录，不继续原先误解的任务。

## 完成、阻塞与恢复

任务达到全部验收后才设 Done，填写 `completion.summary`、真实通过的 `checks` 和可定位 `evidence`；自动校验只验证这些字段和路径，不证明证据内容正确。关键检查失败不能靠文档关闭任务。更新覆盖台账，再将已满足依赖的下一任务设 Ready。

当前线完成后，需要核对覆盖台账的关闭条件，才设 Done 并激活下一条线。同线还有未完成任务时不能提前关闭。

实际缺少工具、文件或必要用户裁决时设 Blocked，并填写具体 `blocker`：缺什么、已经尝试什么、如何解除。只有“耗时长”“可能复杂”不能构成阻塞；继续独立可做的部分。恢复时回到同一合同，解决阻塞后改回 Active。

同一任务未完成时持续推进；上下文压缩不是停止条件。只有未保存的信息影响恢复时，才在合同附一个简短检查点，记录已做、未做和下一步，不另建平行状态源。

状态修改后运行：

```powershell
npm run generate:harness
npm run check:harness
```

普通“执行/继续”完成当前任务后交回结果，说明新选中的下一项；不会因当前任务完成自动连续开发完整游戏。若用户明确要求多个任务，则逐个验收后继续其授权范围。

## 分工角色

| 角色 | 工作 | 写入边界 |
| --- | --- | --- |
| 源资料研究员 | 追踪脚本、时间轴和证据，识别未知 | 默认只读；明确分配后可写自己的报告，不改原始材料 |
| 实现工程师 | 根据已验证合同写现代代码/转换工具 | 当前任务指定文件；不制造原版事实 |
| 独立评审员 | 核查证据、行为、回归、验收缺口 | 默认只读，返回可操作发现 |
| harness 维护员 | 路由、状态机制、校验工具 | 分配的 harness 文件，不夹带玩法实现 |

主 agent 对结果负责。沿用客户端默认模型，无项目级强制模型、自动审批或额外权限配置。
