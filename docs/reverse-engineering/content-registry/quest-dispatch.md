# 任务目标与奖励分发

动态目标注册见 `src/content/quest-generator-rules.ts`，执行对照见 `tests/quest-generator-source.test.mjs`。指挥官命令3201–3207提供七组普通怪与首领目标，第七组首领通过random(2)二选一；军功需要两个目标各6个，功勋添加“精英”后缀并各需4个，悬赏需要1个首领。3211–3213将这些名称传给setDailyTask。好友委托random(4)的前三支收集三种晶石，第四支按homeCity选普通怪4个及精英2个，未知城市默认龙怪。测试逐个执行七组初始化、两种高级首领和全部好友分支。测试不证明NPC菜单可达性。

setDailyTask倒序找到同名任务后替换需求、设置isDoing，但不检查已有isDoing且不清除isComplete。setFriendTask拒绝已在进行的好友任务，其他情况下同样不清除isComplete。不能把常规新任务初始化假设加到原版合同中。

固定名称目标通过 `tools/lib/objective-registration-evidence.mjs` 独立扫描原脚本、执行字面对象并对账39种身份和91处声明。该检查明确排除动态名称表达式；动态输入集合由上述生成规则补充，不能把固定目标数量称为全部可能的目标名称数量。

源：`DefineSprite_2210_任务系统/frame_1/DoAction.as` 的 `catchThing`（286行）、`getPrize`（465行）。正式规则为 `src/content/quest-dispatch-rules.ts`，源函数执行对照为 `tests/quest-dispatch-source.test.mjs`。这里只确认面板中的分发与状态写入，不确认下游物品效果、角色 setter、确认弹窗回调或完整任务流程。

## 目标计数

taskComplete每次先把isComplete置true，再倒序检测需求，任何number<needNumber即置false并退出。无需求时直接完成；计数超过需求也视为完成。这是重新计算标记，不沿用之前的标记。

有 type 的输入按对象处理：name 未定义时使用 type；number 未定义或等于零时数量取1。无 type 的输入直接作为目标名称，数量用第二参数。仅 NaN 被拒绝；零或负数没有额外检查。

按任务组、任务、需求三层倒序查找。任务必须进行中、等级满足、目标名称匹配且计数未满。匹配后只填充该目标，立刻返回 true，不把剩余数量分配给其他任务。原对象 number 非零且有定义才回写剩余数量。完成检测后主线可触发 nextMainTask；显示刷新调用不属于本项行为验证。

## 奖励分发

七种特殊奖励由 `tools/lib/reward-registration-evidence.mjs` 独立扫描源对象进行逐字段对账，涵盖119处声明（魔石12、资源26、军功33、功勋33、声望13、接荣誉任务1、出征3个幻兽1）。唯一动态val是好友等级公式，检查保留原表达式并在三个输入上执行对照；其输入可达范围不由该对账确认。篡改奖励数值的负向测试确保检查不是只核数量。

无当前任务、明确未完成或未进行时拒绝。荣誉任务要求去国王处领取，面板不发奖。奖励数组倒序处理；魔石、资源直接增加相应 xxx 字段，军功、功勋、声望调用角色方法，三幻兽奖励写 maxBattleNum=3，荣誉任务接取通过确认弹窗回调。

八种装备类别先 upDataWeapon 再 backPack.setThing。其余奖励 number>0 时从整数0循环到 number 之前，每次调用 createThing；因此正小数会产生向上取整次数。其他数量调用一次。工厂和背包返回值未检查，没有事务或回滚。日常任务清零需求并取消完成标记，所有领取任务取消进行标记，清除面板当前任务。

好友委托先清除 friend.isTask，按好友总等级 L 设置魔石 L*10+100。floor(L/7) 的0至5分别给奇异兽、6星、8星、12星、15星、19星奇异兽；其他值给23星奇异兽。测试覆盖分桶边界以及负数和高值输入，但不声称这些输入均可在正常游戏中达到。

源执行测试验证首匹配与剩余数量、负数与零数量、奖励倒序、装备分发顺序、普通工厂失败后仍重置任务、好友分桶和荣誉任务拒绝领取。源规则不是现代系统设计建议；以后玩法实现应明确处理源异常与兼容要求。
