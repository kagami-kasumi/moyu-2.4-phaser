# 其余源恢复字段的写入语义

本合同记录readGame中原赋值及后续已观察操作，不把字段类型检查、默认填充或派生值重算冒充原版行为。

直接字段包括全局进度、角色姓名/职业/技能附加值等普通属性、商店解锁数、地图地点/产权/幻境标记、首领成长、XP状态、称号计数、PK胜利标记、朋友容量、幻兽出战容量。它们按源顺序直接赋值；条件保存在字典每个load记录中。普通属性缺值可能写入undefined，不能沿用数值编码setter“缺值忽略”的结论。六个XP格显隐为MovieClip原生属性，记录原赋值，不用普通JavaScript对象推断全部AVM1转换规则。

军衔、爵位、职位的显示名先从存档读取，之后相关数值setter可能覆盖它们。首领成长和称号计数使用当前表长度迭代，非存档数组长度；首领循环里的_loc4_初始化0但不递增。XP数量、满标记、格显隐彼此独立恢复，没有统一一致性修复。

versions是控制信息，不赋给当前游戏版本。readGame先检查当前moyu_so的版本，再getLocal请求槽位；不能描述成先打开槽位再检查。后段若读取版本低于当前版本，则幻兽商店容量20、解锁数加3；商店容量16、原解锁15时改16；城堡宝石商店容量/解锁均8。现代版本迁移需设计明确，不能未经说明复制这一旧引用检查顺序。

幻兽长度用于清空后的重建循环；每个构造完成又checkUp一次，全部完成后afterAdd。sd/qyg重复nextLvRate键仍按已登记的源异常处理。这里没有宣布已解决AVM1重复键行为。

本批覆盖此前缺少restoreSemantics的81个模板；有了描述不等于最终存档schema完成。当前仍需独立字段集合对账、完整恢复顺序及现代保留结构验收。
