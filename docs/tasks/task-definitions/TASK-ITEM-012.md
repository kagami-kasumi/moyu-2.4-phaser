# TASK-ITEM-012 · 装备魔魂强化闭环

## 目标
玩家打开现有魔魂礼包获得材料，将四类装备的魔魂等级提升，查看重算后的攻击/防御和穿戴战斗力；材料不足或达到源上限时不误扣。

## 输入
- TASK-ITEM-011 的打造双槽、取回与满包回收，以及 TASK-ITEM-008 的礼包使用和装备属性。
- 根 `local-resources/moyu/source-index/as/scripts/frame_9/DoAction.as` make.flashInfo 的魔魂晶石/魔魂之心分支（约3118）、makeItem 的同名分支（约3672）、useGem(3356)、upDataWeapon(5232)、equipment.flashAttribute；对应 P-code 已有。
- 当前魔魂礼包已生成魔魂之心，可从真实冷启动操作链取得；原初始装备含魔魂+9武器和+3防具。
- 选题理由：开孔已建立打造入口，背包现有大量魔魂礼包尚不能用于强化；用同一物品旅程连接消耗、装备重算和实际属性反馈。

## 范围
有界源取证、独立冻结期望、魔魂晶石/魔魂之心强化及打造面板扩展，覆盖四类装备、源品质关联上限和材料消耗。戒指/幸运符独立打造分支不扩展，品质升级、装备升级、镶嵌、战斗和存档不在范围。界面以清晰为准，外观标 design。

## 输出
`docs/reverse-engineering/equipment-magic/` 源合同、冻结基准、验证报告；领域和打造界面扩展、逻辑/浏览器测试。

## 验收
- 冷启动领取装备，使用魔魂礼包，选择装备/材料强化、取回穿戴；魔魂等级、魔魂攻防、售价与人物属性按源重算，其他属性不意外改变。
- 独立源期望覆盖0/18/19及品质5/6的37/38/49/50边界、晶石按下一级×2消耗、之心单件消耗、数量不足、零数量单件、堆叠、上限拒绝、非法装备、重复/过期操作、替换/关闭/取回、满包回收、切图和新建。
- `npm run typecheck`、`npm test`、`npm run build`、`npm run test:browser`；正常无probe链及受控边界有实际截图检查，保持开孔/兑换/拾取/装备/地图及44动作回归。
- 更新覆盖台账与调度，运行 `npm run generate:harness`、`npm run check:harness`。只有源解析器或资源修改时追加对应源检查。

## 停止与拆分
先核对完整分支、材料不足与重算顺序，再实现；关键未知项继续精确AS/P-code取证。仅真实外部依赖可阻塞，不按技术阶段或上下文长度拆任务；完成后落实下一项。
