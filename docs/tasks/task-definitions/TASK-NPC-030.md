# TASK-NPC-030 · 老兵等级奖励与成长领取闭环

## 目标

玩家使用已实现的经验成长后返回老兵，按原版等级门槛逐档领取宝盒、资源或魔石，保存恢复领取进度且不能重复领取同档。

## 输入

依赖TASK-EQUIP-029及既有成长、老兵礼包/兑换与保存。选择理由：当前老兵“是否有等级奖励”尚被省略，人物经验球成长已可达各档，补齐现有起始区域成长反馈与装备开孔材料途径；不是新增孤立道具。

`DefineSprite_4312/frame_1/DoAction.as:270–385`的cmd6、8–17：三个奖励档、严格大于levelPrize*10、九种分支、先推进索引再发奖。cmd13文案100,000但实际加50,000，须AS/P-code确认并记录差异。`frame_9/DoAction_2.as:32,383,1707`初值upLevelPrize=1及保存恢复。现有奖励源oracle、货币setter、背包源可复用但不覆盖旧冻结。

## 范围

全部三档/九分支、等级10至150边界、逐次补领、宝盒堆叠/满包落地、资源魔石封顶、领取计数与首次礼包标记独立、离开与返回。原版阈值是严格大于，不擅自改为达到即可领取。现代说明可明确“超过”及真实发放数量，设计文案与原事实分开。

加入真实老兵菜单与对话流程，领域状态、原upLevelPrize推广和GameProgress保存；异常/过期选择、切图/新建和备份/导入都保持不重复。其他NPC、战斗、城堡和远区不含本次。

## 输出

独立源合同/冻结函数、领域规则与真实对话、字段归属、覆盖台账、源对照逻辑和浏览器验证报告。

## 验收

- 源oracle逐档九分支与等级门槛上下各一点、1..15奖励索引、两职业、满包/堆叠、货币封顶及余额全对照，确认cmd13实际数值。
- 两职业无probe：领取礼包→经验球成长→老兵选奖励→继续成长补领→宝盒用于开孔→保存刷新与真实导出导入；没有升级不开放领取，150级不凭空领取150档。
- 反复点击/旧按钮、返回/取消、切图、新建、旧raw计数推广、未实现字段保留、领取先后顺序与地面回收通过。
- `npm run typecheck`、`npm test`、`npm run build`、`npm run test:browser`、`npm run check:save`；实际截图复核；generate:harness/check:harness。

## 停止与拆分

全部等级奖励属于一个完整能力，不按档位/奖品拆分。仅实际缺少源文件、工具或必要用户决策可阻塞；文案与发奖不一致须保留证据、明确现代说明，不自行改变奖励平衡。
