# TASK-EQUIP-042 · 装备回收与经验球兑换

## 目标
玩家将闲置装备兑换为经验球或分解为打造材料，取回使用产物，保存持有状态并在刷新/导入后继续回收。

## 输入
依赖TASK-NPC-041。选择理由：四类装备全打造与材料打包已连通，闲置装备除出售外缺少原版回收闭环；回收产物直接服务经验成长和既有打造。源4312/frame1/DoAction_2.as的testToExp/weaponToExp/testToBreakUp，cmd161–163；2111_给予物品/frame1的give/setThing，原createThing和背包规则；现有装备、仓库、经验球、存档消费者。

## 范围
经验兑换覆盖原四装备与三铃铛类型；分解覆盖四装备全部已支持品质、孔数、等级、魔魂和元素组合。持有槽明确归属、选择/替换/取回、确认/取消、旧回调和切图隔离，持有物/产物存档。新增背包“装备回收”入口属于design；经验导师所在城三尚未开放，不伪称地图或NPC已完成。源正数量装备不清槽异常必须记录并明确防重放设计，不能默默复制产物。

## 输出
冻结源函数及独立矩阵、回收领域与界面、持有槽持久化、两职业正常装备回收/成长/打造旅程、验证报告和覆盖台账。

## 验收
- 原源比较七类型经验数量、四类型各品质/孔/等级/魔魂/元素分解的输出顺序、字段、满包掉落及消息；品质6无基础产物、魔魂循环上限等不能猜测修正。
- 两职业无probe礼包装备→兑换经验球→使用成长，另件装备分解→材料用于既有打造；持有/已产出状态刷新和真实文件导入。受控全组合、满包、取消/旧按钮/切图/新建和未知字段保留。
- typecheck、npm test、build、test:browser、check:save及generate:harness/check:harness；实际查看截图；不损坏既有仓库/打造/打包。

## 停止与拆分
两种原回收能力共享一个归属与旅程，完整交付；不按取证和实现阶段拆分。铃铛自然获取/打造、城三NPC和军功捐献另排，不能吞入本项。只有实际外部依赖才阻塞。
