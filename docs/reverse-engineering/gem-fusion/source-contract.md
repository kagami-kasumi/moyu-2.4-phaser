# 宝石融合源合同

verified：frame9/DoAction.as的castleStone.setThing、notice、flashInfo、beginRefine与yesButton；冻结完整函数及AS/P-code哈希见source-functions.json。原文件只读。

setThing接受任何宝石，先填主槽再填副槽；两个槽均满则拒绝。整格物品移动，不拆堆。beginRefine只识别四种高级宝石：同类时主战斗力<8免费+1；8≤主值<15且声望≥主值−6时扣声望后+1；攻击<25时+2、减伤<13时+1、经验<35时+2。副材料数值不限制。按判定前阈值执行，因此攻击24→26、经验34→36是原行为，不能强行封顶。

战斗力宝石与攻击/减伤/经验的任一组合（两种顺序）生成对应圣石，val1来自战斗力、val2来自另一宝石；无声望费用。主槽替换为新对象，副槽清空。主槽原叠数/其他字段不继承，整格副材料消耗；输出number经ThingMC缺省归0。四同类输出售价分别2000/1000/1000/1000（经验初始店买500但融合后1000）；圣石3000。成功按钮消息“宝石融合成功”；收费先发“声望 -N”，失败不发成功消息。融合无随机；满包取回复用已验证背包掉落。

design：现代背包入口、显式两选择框、revision和角色归属校验。取回维持既有整格背包/掉落语义。城堡入口/经营未开放，不把现代入口称为原版获取路径。双槽扩展独立保存，并推广已注册castleStone_stone1/stone2字段；未知旧物品保持opaque，不因无法实例化被覆盖。界面关闭和切图不返还材料，新建才重置。
