# 工程评审协议

评审目标是发现会影响后续 SWF 提取、时间轴消费和脚手架维护的问题。评审不代替实现，也不建立旧项目的 PG 治理系统。

每条发现必须包含：严重程度、证据路径和定位、可观察影响、修复范围、验证方式。严重程度使用 `P0`（无法继续或源数据损坏）、`P1`（会产生错误资源/时序或阻断交接）、`P2`（局部质量问题）、`P3`（改进建议）。没有可定位证据的内容写成疑问或风险，不写成确定缺陷。

评审顺序为：源清单与哈希 → 提取产物完整性 → sprite/frame/Action 定位 → pivot/矩阵/持续时间 → expected/actual 是否独立 → 规则事件与渲染回调是否解耦 → 未来 Phaser 适配边界。涉及视觉或命中时，明确哪些是 `verified`、`inferred`、`unknown`、`design`。

评审输出只覆盖本次范围，给出最小修复和对应命令。不得用构建成功替代视觉、时间轴或碰撞验证，也不得把旧项目 AS3/EVB/AIR 经验当成本项目 AVM1 的源事实。没有游戏实现时，评审应聚焦 harness、清单、提取工具和文档链接。
