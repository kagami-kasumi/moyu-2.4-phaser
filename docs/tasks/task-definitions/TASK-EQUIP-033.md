# TASK-EQUIP-033 · 装备魔之魂十类属性附加

## 目标
玩家将魔之魂十类属性附加到两职业四装备，覆盖既有魔之魂，穿戴后显示真实属性与战斗力，并保存继续。

## 输入
依赖TASK-EQUIP-032。选择理由：四装备重铸与元素已有完整消费者，魔之魂参数化十类属性是该装备旅程尚未接入的完整属性机制；不是按十个效果拆成十任务。源frame_9/DoAction.as:3915–3927的makeItem魔之魂分支、2115–2157和2227的soulFire/val1/val2属性汇总、createThing魔之魂工厂。复用equipment-magic和equipment-elements独立完整冻结。获取由矿洞/战斗等后续负责，本次不虚构常规获取。

## 范围
十类val1：攻击、防御、生命、魔力、攻击百分比、防御百分比、生命百分比、魔力百分比、暴击、闪避；val2原值。材料参数缺失时源将两值设1；覆盖旧属性，材料堆叠/单件消费、数值0与未知类型参数按源保留。单件数值有效即贡献5战斗力，四件叠加；与元素套装、魔魂、品质、孔和戒指组合。共享打造槽、材料提示、单件与人物展示、持有/穿戴保存和旧raw保留。

## 输出
参数字段源合同、独立引用/oracle、领域与UI消费者、全目录源矩阵、真实浏览器/存档验证和覆盖台账。

## 验收
- 两职业四装备×十属性及0/缺失参数、覆盖/消费数量边界；全对象/材料消息源对照，无随机调用。
- 全十属性、四件叠加、其他装备效果组合，与完整源装备和人物函数比较，不能只用实现公式做expected。
- 两职业受控材料输入后真实附加→覆盖→穿戴→保存刷新/真实导入；正常缺材解释；旧回调、满包、关闭/切图/新建。
- npm run typecheck、npm test、npm run build、npm run test:browser、npm run check:save、实际截图；generate:harness/check:harness。

## 停止与拆分
本次仅魔之魂参数化附加；玄铁附加、陨铁战魂及其战斗成长另属机制，不混入其thisallItem源异常。材料获取和战斗伤害不作已完成声明；只有真实输入缺失才阻塞。
