# TASK-ITEM-023 · 人物消耗品与储备资源机制包

## 目标

玩家通过背包使用已注册的人物消耗品，看到即时生命/魔力恢复、储备资源消耗、永久属性或XP容量变化，并能保存和恢复；按共享消费链成批覆盖，不再逐个道具建任务。

## 输入

- 依赖TASK-GROWTH-014及TASK-SAVE-022；人物等级、属性、普通经验球、完整保存/恢复已提供接入点。
- 选择理由：人物可升级后，背包大量已注册的状态消耗品仍不可使用。先补消费/属性/持久化共同机制，再进入战斗、技能及区域旅程。
- 有界调查确认 `local-resources/moyu/source-index/as/scripts/frame_9/DoAction.as:275–337`：超级经验球/能量药水调用rolePanel；药品mp给人物，hp按人物与三个已出征幻兽的生命缺口严格比较选目标；生命之源/魔力源泉调用人物及幻兽面板。不能把所有药品简化为只恢复人物。
- 同文件`createItem`约4700–4726列出两种储备资源和七种普通药品（小/中/大型生命药、小/中/大型魔力药、超级药）；完整集合需从注册目录与独立源枚举对账，不能以该行列表代替覆盖证明。
- `DefineSprite_4591/frame_1/DoAction.as:52–148`含超级球等级次数限制/五项加成、能量容量上限、药品与储备分支。RoleMC的生命/魔力setter、Sourse字段、flashAttribute为属性及资源真值。
- 复用`src/content/role-vital-rules.ts`、`role-attribute-rules.ts`、`xp-energy-rules.ts`，017/018数值注册、019持久字典。XP源入口`DefineSprite_4603/frame_1/DoAction.as`及`tests/xp-energy-source.test.ts`可用。
- 既有backPack计数/扣除冻结函数与存档opaque保留可复用；AS及对应P-code存在。Ready仅表示范围输入明确，完整源取证在本任务内完成。

## 范围

共同人物消费链：全部七种药品、生命之源/魔力源泉、超级经验球、能量药水；目标选择、数值上限、成功后扣除、永久加成、储备容量/当前量、HUD与持久化。普通经验球沿用014并回归。

纯规则保留源幻兽目标优先级并用独立输入验证；未开放的出征/合体界面不得伪装完成。转世/成神属于独立角色生命周期，幻兽专用品属于幻兽机制；战斗受伤/XP充能/技能释放和商店采购不在本次开放范围。不能为演示补造受伤按钮或假造材料来源，正常路径使用已有合法入口；伤害与库存边界采用明确受控验收。

## 输出

`docs/reverse-engineering/character-consumables/`完整集合、源合同、冻结oracle及验证；纯领域消费/储备状态模块、人物属性/HUD/背包接入；源字段所有权映射及逻辑/浏览器验收。沿用schema v1和库v2，只有证明现有格式无法承载才考虑迁移。

## 验收

- 独立源枚举对账所有机制条目，无遗漏/重复；AS/P-code哈希及冻结函数独立对照，不用正式规则生成expected。
- 全部药品值、mp与hp先后、相等/不等生命缺口、死亡/满值、单件/零数量/多堆、扣除失败和当前槽语义、储备不足/恰好/溢出与不扣道具、升级后储备容量变化均有源oracle。
- 超级球次数随人物等级限制、五项加成及重算顺序、能量容量3至6及封顶保留、已有英勇/装备/戒指组合；未开放技能不得因容量变化自动启用。
- 两职业无probe正常消费显示真实反馈；关闭/重开、旧按钮、切图、新建重置；受控恢复与不足边界截图实际检查。
- 保存/刷新继续、导出/导入/备份恢复保留全部新活动字段及未实现raw；重复恢复不再发放效果。保留014经验球与全部既有动作/地图/背包/打造回归。
- `npm run typecheck`、`npm test`、`npm run build`、`npm run test:browser`、`npm run check:save`；更新覆盖、下一合同与调度，`npm run generate:harness`、`npm run check:harness`。
