# TASK-SLICE-004 · 首个可玩闭环

## 目标

把已通过动作试点的现代角色接入一个有源证据的最小玩家旅程。本次有界旅程为新建男战士 → 卡萨诺城郊区地面移动/停步 → 通过 entry2 进入卡萨诺城一的 entry1。目的地、入口关联已见源脚本，具体坐标、碰撞、可见资源与防止重复切图的条件须在本任务取证里程碑补齐。

## 输入

- TASK-RE-002 的 [动作合同](../../reverse-engineering/first-actor/action-contract.md)、[验证报告](../../reverse-engineering/first-actor/validation.md)、`src/` 和 `public/assets/first-actor/`。
- TASK-RE-001 的源入口索引及这个切片所需的额外行为证据；选定旅程所需的有界逆向纳入本任务的取证里程碑，证据确认后才实现对应行为。
- [本线关闭合同](../feature-line-coverage/LINE-FIRST-PLAYABLE.md)、[质量门禁](../../workflow/quality-gates.md)。

- 精确源入口（相对 `local-resources/moyu/source-index/as/scripts/`）：根帧3/4/5的新建与男战士选择；`DefineSprite_4536/frame_2/DoAction.as` 的 initNewGame；`frame_8/DoAction.as:1–5` 的 entry2.toMap="卡萨诺城一"、toEntry="entry1"；`frame_1/DoAction.as` 的 Activities、jumpMap、jumpToMap、allowJumpMap；`__Packages/groundMC.as` 的 onPress 与 `RoleMC.as:1198–1400` 八向移动。对应P-code和XML仅按这些路径及目的地标签窄查。

## 范围

激活前根据已有索引指定有界调查对象与预期旅程范围；本任务先补证，将具体操作、反馈及结束条件写入合同，证据门禁通过后才实现。实现前指定一个真实入口、场景、操作、反馈和结束/重试条件。只实现这些直接依赖；不预设横版/俯视/回合制，不自动加入敌人、装备或存档。

内部里程碑：先复核上述入口与地面/出口的显示列表、碰撞和切图控制流，产出独立源基准、操作预期与异常路径；再实现新建入口、源场景资源与移动、一次切图闭环；最后在浏览器从冷启动重走并回归本任务动作工程。地图NPC可见资源按源处理，本次不加入NPC任务系统、战斗、背包、成长或存档。原流程若有额外直接前置，在同一任务补证；无关能力另立合同。

## 输出

一个可冷启动的可玩切片、独立行为与视觉证据、对应自动回归和仍未覆盖的内容表。

## 验收

- 取证验收：对上述源路径的AS/P-code及原标签交叉检查，定位舞台坐标、可通行区域、entry2/目的地entry1和切图保护条件；用独立源画面/几何基准验证，记录verified/inferred/unknown。具体输入序列和边界期望落盘后才能实现，不能从画面bounds猜可通行区域。
- 玩家旅程验收：新建男战士，进入城郊，地面移动并松开停步，抵达entry2后进入卡萨诺城一的entry1；以该次真实场景到达作为本切片完成点。冷启动再走同一旅程是重试验收设计，不伪装成原版重试按钮。越界移动、入口不可见/透明时不跳图、切图不重复触发等预期须经上述取证确认后测试。
- 执行工程已有的类型、行为、构建、浏览器与视觉检查，以及 `npm run check:harness`。
- 用户旅程按源合同可重复完成；原版 expected 与现代 actual 独立生成，覆盖切片中的关键异常路径。
- 从正式资源运行，不依赖原 SWF 执行层或临时验收工具；明确本次只是首个切片。

## 停止与拆分

范围无法形成单个可验证旅程、原版流程仍未知或需要新机制证据时，先收窄/补证，不用宽泛的“游戏可运行”替代验收。完成后据剩余源内容制定下一项，不自动扩展全游戏。
