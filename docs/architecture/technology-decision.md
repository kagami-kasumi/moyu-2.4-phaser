# 技术选型 · 2026-10-05

## 决定

采用 **Phaser + TypeScript + Vite**，目标为现代浏览器原生重写。Phaser 版本基线为 **4.2.1**；TASK-RE-002 已安装并验证该版本，TypeScript 7.0.2、Vite 8.3.2 的精确版本及依赖记录于 package-lock.json；本机 Node 24.6.0 验收通过，Vite 要求 Node ^20.19.0 或 >=22.12.0，本项目最低 >=22.12.0。原文件分析使用已有 FFDec 和离线工具，运行时不引入 Ruffle、Flash 插件或 SWF 播放层。

当前交付包含 harness 与男战士原动作验收工程，有 dev/build、类型、行为与浏览器验收命令；完整地图和玩法尚未实现。

## 为什么继续选 Phaser

项目目标是可二次开发的 2D 浏览器游戏，用户判断本作动作较简单。Phaser 已有场景、输入、资源、音频和 2D 呈现能力，配合纯 TypeScript 规则层能减少基础设施开发量。原版动作简单是用户给定的范围判断，尚不是通过全面逆向证明的事实。

不能仅凭旧项目动作误差得出“Phaser 无法还原”。Flash MovieClip 的嵌套时间轴、注册点、负缩放、持帧、动态脚本和命中事件，需要资源转换与现代运行逻辑共同处理。Phaser 的帧动画能力可用，但不是 Flash 运行语义的自动替代品。参考项目中发现过注册点/镜像与时钟耦合问题；这里只采纳教训，不对旧项目做完整根因裁决或宣布其废弃。

## 备选比较

| 方案 | 对本项目的价值 | 代价与结论 |
| --- | --- | --- |
| Phaser + TS + Vite | 浏览器优先，已有游戏基础设施，规则可独立测试 | 仍须做证据提取和投影适配；当前采用 |
| PixiJS + TS | 渲染层控制直接，适合定制显示树 | PixiJS 自身不是完整游戏引擎，场景/输入/音频等需自行组合；只有最小案例证明 Phaser 适配不合适时再评估 |
| Godot | 编辑器与原生端流程适合桌面/移动优先项目 | 网页导出增加另一套构建和 WASM/WebGL 运行链；不能自动还原 Flash 时间轴，当前目标不需要 |
| SWF 播放/模拟层 | 可运行旧逻辑作为一种迁移方向 | 不符合用户本项目明确要求，排除 |

Phaser 3.90.0 仍是旧项目使用的已发布 3.x 版本；新仓库没有旧代码迁移包袱，因此以核验到的 4.2.1 为基线。若试点暴露明确回归，记录复现案例再固定兼容版本，不把主版本升级当成动作精度保证。

## 必须先通过的动作试点

1. 从一个真实角色提取实际存在的待机、移动、普攻动作；保持原帧/纹理与可追踪标识。
2. 数据明确每帧时长、注册点、裁剪偏移、父子变换、可见边界；碰撞形状单独保存，不从画面 bounds 猜。
3. 面向左右朝向、持帧、状态切换、暂停/恢复做源画面对比。不能把 `flipX` 当成等价的 Flash 注册点镜像；根据坐标定义显式实现并验收。
4. 玩法和伤害事件由独立逻辑时钟驱动，渲染帧跳过不能漏命中或重复结算。原 SWF 声明 15 FPS，但 setInterval、脚本跳帧等需要另查。
5. 先验证基准、误差和帧率变化，再接入首个可玩闭环。只有最小可复现案例证明引擎能力阻碍目标时，重新评估 PixiJS/Godot；先排除源提取和转换缺陷。

不建立通用 Flash 解释器，不预建 ECS、万能事件总线、嵌套时间轴虚拟机或复杂设计模式。按实际源行为逐步增加必要适配。
