# TASK-PET-048 · 幻兽收藏整理与释放

## 目标
玩家在40容量内按出征记录/评分/等级浏览四格分页，选择详情并确认释放未出征幻兽腾出容量；释放、继续孵化和存档恢复不混淆对象及旧档字段。

## 输入
依赖TASK-PET-047。选择理由：全蛋孵化完成后，收藏只能堆积、满40无法继续；需要可用的管理闭环。frame_9/DoAction.as:2426..2508的add/afterAdd/sort/show/drop/del/prePage/nextPage；046详情、047完整初始化、40容量与pet数组保存。

## 范围
所有25物种/固定随机记录的降序排序、稳定同分处理、四格分页、详情选择、未出征对象二次确认释放、容量回收和字段归属。排序投影不改变存档索引；释放实际移除对象。原版允许先召回再丢弃，本项目召回未开放，因此保护battle=true记录并明确提示，是design限制，不宣称召回/出征完成。出征、合体、战斗、成长与铃铛不在本项。

## 输出
纯收藏领域模块、分页/释放UI、旧档对象字段随记录移动的无损存档、独立源比较和两职业正常孵化/释放/再孵化报告。

## 验收
- 源枚举证明三项降序和四格页、原身份删除与确认；0/1/4/5/39/40容量、分数/等级同值、删除末页、未知评分、取消/双击/旧按钮/切图/新建。
- 两职业无probe多次孵化、排序分页、取消后确认释放、再孵化与详情；保存刷新和真实导入，初始出征记录不可释放。受控40容量与同物种不同参数/未知raw字段删除归属。
- typecheck、npm test、build、check:save、收藏浏览器和详情/孵化/商店/背包相关回归、实际截图；generate:harness/check:harness。

## 停止与拆分
以完整未出征收藏管理交付，不为开放释放暗中实现战斗或假召回。无法确定对象关联必须拒绝，不能靠索引或同名猜测删除目标；未知原始字段保持与其所属对象关联。
